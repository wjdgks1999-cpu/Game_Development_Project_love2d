# 경기 판정 구현 계약

## 1. 목적과 권위

이 문서는 `05_pitching_match_and_balance.md`와 `06_progression_quest_and_career.md`의 확정 설계를 코드로 옮길 때 사용하는 계산 순서, 데이터 경계와 재현 검사를 정의한다.

- 경기 경험, 판정 의미와 밸런스 목표는 `05_pitching_match_and_balance.md`가 소유한다.
- 훈련 점수, 성장과 상태 수치는 `06_progression_quest_and_career.md`가 소유한다.
- 이 문서는 위 규칙을 바꾸지 않고 구현 가능한 계산 계약으로 연결한다.
- 원본 GDD와 충돌하면 원본 권위 문서를 먼저 수정한 뒤 이 계약을 갱신한다.
- 이 문서에 새로 등장하는 확정되지 않은 계수와 좌표 규칙은 `[가정]`이며 데이터에서 조정 가능해야 한다.

## 2. 공통 단위와 좌표

### 2.1 시간

- 모든 판정 시간은 초 단위의 단조 증가 실수값을 사용한다.
- 렌더 프레임 번호는 판정 입력으로 사용하지 않는다.
- 터치 로그에는 원본 시각, 보정 시각과 보정 근거를 함께 남긴다.

### 2.2 포구면 좌표

- [가정] 포구면 중심을 `(0, 0)`으로 둔다.
- [가정] 스트라이크존의 좌우와 상하 경계를 각각 `-1.0~1.0`으로 정규화한다.
- 투수 기준 팔 쪽·글러브 쪽 방향과 화면 좌우 방향을 별도 변환 함수로 관리한다.
- 실제 화면 좌표는 판정 전에 포구면 좌표로 변환하며 화면비와 안전 여백은 판정에 영향을 주지 않는다.
- 목표 가능 영역은 `05`의 스트라이크존 바깥 공 한 개 너비 원칙을 데이터 값으로 변환한다.

## 3. 릴리스 판정

정규화 릴리스 오차 `R`은 다음처럼 계산한다.

```text
R = (보정된 실제 터치 시각 - 이상적인 릴리스 시각) / 유효 반폭
```

- `R < 0`: 빠른 릴리스
- `R = 0`: 중심 릴리스
- `R > 0`: 늦은 릴리스
- 유효 반폭은 구종, 제구, 멘탈, 컨디션과 피로로 계산한다.
- 입력 등급 경계는 `05`의 `정확·양호·불안정·실수` 구간을 사용한다.
- [가정] 유효 반폭 계산식과 각 영향 계수는 `BalanceConfig`에서 관리한다.

## 4. 실제 투구 위치

```text
실제 위치 = 목표 위치
          + 릴리스 방향 오차
          + 제구·숙련도 산포
          + 멘탈·피로 상황 오차
```

### 4.1 릴리스 방향 오차

```text
크기 = release_curve(abs(R), pitch, condition)
방향 = release_direction(sign(R), throws)
릴리스 방향 오차 = 방향 × 크기
```

- `release_curve`는 입력 오차가 커질수록 비선형으로 증가한다.
- 빠른 릴리스는 투수 기준 높은 쪽·팔 쪽, 늦은 릴리스는 낮은 쪽·글러브 쪽을 향한다.
- 큰 오차도 데이터에 정의된 최대 범위를 넘지 않는다.

### 4.2 제구·숙련도 산포

```text
산포 반경 = 구종 기본 산포
          × 제구 계수
          × 구종 숙련도 계수
          × 컨디션 계수
          × 피로 계수

산포 = pitch_spread 난수 스트림으로 제한 타원 안을 표본 추출
```

- 능력치가 높아질수록 각 계수는 산포를 단조 감소시킨다.
- 산포는 0이 되지 않으며 작은 난수만으로 명백한 실투를 만들지 않는다.
- 타원 축, 최솟값, 최댓값과 분포 방식은 `BalanceConfig`에서 관리한다.

### 4.3 멘탈·피로 상황 오차

- 멘탈 단계와 피로 단계가 불리할 때만 추가된다.
- 같은 `pitch_spread` 스트림에서 별도 호출 순서를 사용한다.
- 상황 오차만으로 자동 볼넷이나 자동 실투를 만들지 않는다.
- 릴리스·기본 산포·상황 오차와 최종 제한 전후 값을 로그에 남긴다.

## 5. 한 투구의 결정 순서

다음 순서를 바꾸지 않는다.

1. 경기 상황 스냅샷 고정
2. 구종·목표·포수 사인 기록
3. 릴리스 `R`과 입력 등급 계산
4. 실제 위치·구속·움직임 계산
5. 타자 예상 구종·코스와 접근 방식 결정
6. 지켜보기 또는 스윙 결정
7. 헛스윙 또는 접촉 결정
8. 파울 또는 인플레이 결정
9. 타구 질·종류·방향·속도·발사각 결정
10. 자동 수비와 주루 결정
11. 실제 기록과 투수 책임 결정
12. 카운트·주자·점수·멘탈·피로 갱신
13. 퀘스트와 공개 사건 발행
14. 다음 투구·타자·등판 종료 결정

각 단계는 앞 단계의 명시적 출력과 자신에게 배정된 난수 스트림만 사용한다.

## 6. 타자·컨택·타구 계약

### 6.1 타자 예상

```text
예상 가중치 = 타자 성향
            + 카운트 영향
            + 최근 구종·코스 기록
            + 반복 패턴
            + 리그 수준
            + batter_decision 제한 난수
```

- 가중치는 확률이 아니라 후보 선택용 점수로 먼저 계산한다.
- 같은 점수·상태·시드에서는 같은 예상 구종·코스를 선택한다.
- 최종 투구 위치를 미리 참조하지 않는다.

### 6.2 지켜보기·스윙과 접촉

- 실제 궤적이 타자의 스윙 가능 범위에 들어오는지 먼저 계산한다.
- 예상 일치, 선구안, 카운트와 적극성을 합쳐 지켜보기·스윙 점수를 계산한다.
- 스윙하면 실제 위치, 구속·구위, 움직임, 터널, 노림수와 컨택을 사용해 헛스윙·접촉을 계산한다.
- 접촉하면 파울·인플레이를 결정한 뒤 타구 질을 연속값으로 계산한다.
- 각 단계의 가중치와 경계는 `BalanceConfig`의 `[가정]` 값으로 관리하며 화면 코드에 넣지 않는다.

## 7. 수비·주루·책임 계약

### 7.1 수비

```text
도달 가능 거리 = 팀 수비력과 체공 시간으로 계산
실제 필요 거리 = 담당 수비수 시작점과 예상 착지점의 거리
```

- 실제 필요 거리가 도달 가능 거리 이하면 포구 후보가 된다.
- 실책은 포구 후보에서만 판정한다.
- 도달 불가능이면 타구 종류·속도·방향에 맞는 안타 후보가 된다.
- 홈런 후보는 일반 도달 판정과 분리한다.

### 7.2 주루

- [가정] 주루는 `타구 결과 × 기존 주자 위치 × 아웃카운트` 데이터 표로 처리한다.
- 도루, 견제, 번트, 런다운, 폭투와 포일 결과는 생성하지 않는다.
- 병살·희생플라이 등 필요한 최소 야구 결과는 데이터 표에 명시된 경우에만 허용한다.
- 표에 없는 조합은 안전한 단순 진루 결과를 사용하고 폴백 사실을 로그에 남긴다.

### 7.3 책임

실제 기록, 가상 아웃, 투수 책임과 공개 사건은 `contracts/02_game_event_contract.md` 형식으로 기록한다. 책임 의미와 가상 아웃 규칙은 `05`를 따른다.

## 8. 첫 프롤로그 제약

`PrologueConstraint`는 첫 1군 프롤로그에서만 다음 순서로 개입한다.

1. 일반 판정 결과를 먼저 계산한다.
2. 이미 한 점 이상의 투수 책임 실점이 발생했다면 일반 결과를 그대로 확정한다.
3. 실점 전의 세 번째 아웃 후보가 발생하면 해당 아웃을 그대로 확정하지 않는다.
4. 현재 입력·구종·위치와 모순되지 않는 비아웃 사건 후보를 선택한다.
5. 나쁜 입력이 있으면 해당 원인을 유지하고, 좋은 입력이면 `batter_good_response` 또는 정직한 수비·타구 사건을 사용한다.
6. 좋은 입력에 `release_mistake`, `location_miss` 또는 `slider_hung`을 허위로 추가하지 않는다.
7. 최소 한 점의 투수 책임 실점 후에는 제약을 종료하고 일반 판정만 사용한다.

로그에는 일반 계산 결과, 대체 결과, 대체 이유, 사용 태그와 제약 종료 여부를 모두 기록한다. 2군·최종 1군 경기에서는 이 모듈을 생성하거나 호출하지 않는다.

## 9. 훈련 점수

각 훈련 투구의 점수는 다음과 같다.

```text
투구 점수 = 목표 코스 점수 × 0.40
          + 릴리스 점수 × 0.40
          + 훈련 과제 점수 × 0.20

최종 점수 = 12구 투구 점수의 산술 평균
```

- 목표 코스 점수는 실제 위치와 지정 목표 사이 거리로 0~100을 계산한다.
- 릴리스 점수는 입력 등급별 0~100 대응표를 사용한다.
- 훈련 과제 점수는 해당 훈련의 공개 과제별 성공 비율을 0~100으로 환산한다.
- 거리 허용값과 입력 등급 점수표는 `06`의 목표를 해치지 않는 `[가정]` 데이터다.
- 최종 등급과 성장량은 `06`의 확정 표를 그대로 사용한다.

## 10. 난수와 재현

- `pitch_spread`, `batter_decision`, `contact`, `batted_ball`, `defense` 스트림을 분리한다.
- 호출하지 않은 단계의 난수는 소비하지 않는다.
- UI·사운드·파티클은 위 스트림을 사용하지 않는다.
- 같은 빌드·데이터·상태·시드·입력·호출 순서는 같은 사건 로그를 만든다.
- 일반 재시도는 새 시드를 사용하고 앱 중단 복귀는 저장된 동일 시드와 호출 상태를 사용한다.

## 11. 최소 테스트 벡터

| ID | 입력·상태 | 필수 결과 |
| --- | --- | --- |
| `MR-01` | `R=0`, 같은 상태·시드 | 실제 위치와 로그가 반복 실행에서 동일 |
| `MR-02` | 같은 크기의 빠른·늦은 `R` | 서로 반대되는 투수 기준 방향 오차 |
| `MR-03` | 작은 난수, 좋은 입력 | 난수만으로 명백한 실투 태그 없음 |
| `MR-04` | 성장 전후 같은 입력 표본 | 성장 후 산포 상한이 증가하지 않음 |
| `MR-05` | 높은 능력치, 명백한 나쁜 입력 | 자동 성공 없음 |
| `MR-06` | 무성장, 좋은 입력 | 2군 성공 가능한 정상 판정 경로 존재 |
| `MR-07` | 도달 불가능 타구 | 수비 실책으로 기록하지 않음 |
| `MR-08` | 가상 아웃 3개 이후 실점 | 퀘스트 투수 책임에서 제외 |
| `MR-09` | 프롤로그의 좋은 입력 연속 | 최소 실점은 발생하되 허위 실투 없음 |
| `MR-10` | 2군·최종 경기 | `PrologueConstraint` 호출 0회 |
| `MR-11` | UI 효과 활성·비활성 | 경기 사건 로그 동일 |
| `MR-12` | 훈련 중단 후 복귀 | 같은 12구 시드와 시작 상태 복원 |

## 12. 구현 전 조정 가능한 값

다음 값은 코드 상수가 아니라 검증 가능한 데이터로 둔다.

- 유효 릴리스 반폭과 상태별 계수
- `release_curve`와 최대 방향 오차
- 구종별 기본 산포와 타원 축
- 제구·숙련도·컨디션·피로 계수
- 타자 판단·스윙·컨택·타구 가중치와 경계
- 수비 도달 거리, 실책 확률과 자동 주루 표
- 훈련 거리 허용값과 입력 등급 점수표

값이 확정되기 전에는 `[가정]`으로 유지하고 `VALIDATION_MATRIX.md`의 관련 검증 결과 없이 `[확정]`으로 바꾸지 않는다.
