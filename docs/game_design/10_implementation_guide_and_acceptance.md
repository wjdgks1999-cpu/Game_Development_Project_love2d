# 구현 가이드와 수용 기준

## 1. 목적

`00`~`09`의 확정 설계를 실제 코드로 옮길 때 AI와 개발자가 따라야 할 구현 순서, 의존 관계, 불변 조건과 수용 검사를 정의한다. 세부 규칙은 해당 기능을 소유한 원본 문서를 따른다.

이 문서는 코드 구현, 기술 검증과 수용 검사만 다룬다.

## 2. 사용 원칙

구현 전 다음을 확인한다.

1. `docs/game_design/INDEX.md`가 지정한 기능 소유 문서와 소비 문서
2. 기능을 소유한 원본 문서
3. 선행 시스템
4. 입력·출력 데이터
5. 로그와 검사 방법
6. 버티컬 슬라이스 포함 여부
7. 불변 조건과의 충돌

다음 작업은 날짜가 아니라 아직 통과하지 못한 가장 앞선 의존 게이트를 기준으로 선택한다. 하나의 작업은 데이터, 로직, 최소 출력, 로그, 검사와 예외 처리를 가능한 범위에서 함께 포함한다.

## 4. 문서와 코드 대응

경기 판정·이벤트·커뮤니티 데이터의 세부 구현 형식은 `contracts/`의 계약 문서를 따르고, 실제 콘텐츠 준비 상태는 `content/CONTENT_REQUIREMENTS.md`를 확인한다.

| 문서 | 구현 대상 |
| --- | --- |
| 00~01 | 최상위 범위와 경험 원칙 |
| 02 | 선수·인물·커리어 설정 |
| 03~04 | 전체 흐름, 장면 전이와 체크포인트 |
| 05 | 직접 투구와 경기 시뮬레이션 |
| 06 | 훈련·성장·퀘스트·커리어 |
| 07 | 공개 사건과 템플릿 선택기 |
| 08 | 화면·입력·아트·사운드 |
| 09 | 런타임·데이터·저장·테스트 |
| 10 | 의존 관계와 종단 간 수용 검사 |

세부 구현은 `docs/game_design/INDEX.md`가 지정한 기능 소유 문서를 따른다. 이 문서는 원본 수치를 덮어쓰지 않는다.

## 8. 검사 계층

- 단위: 릴리스, 산포, 스트라이크, 상태, 훈련 점수, 패시브, 책임, 슬롯
- 시뮬레이션: 동일 시드, 결과 다양성, 프롤로그 격리, 퀘스트·책임·커뮤니티
- 통합: 장면 전이, 보상 중복, 체크포인트, 읽음 상태, 엔딩과 저장 복구
- 실제 기기: 터치, 릴리스 체감, 안전 여백, 30FPS, 앱 복귀, 오디오, 진동과 텍스트

실제 기기 실행 근거가 없으면 기기 관련 항목을 통과했다고 선언하지 않는다.

## 9. 디버그 요구

장면, 선수 상태, 훈련 등급, 퀘스트·패시브, 시드, 카운트·주자, 실책·불운·책임, 프롤로그 제약, 여론·템플릿, 엔딩, 저장 손상과 FPS를 직접 설정·확인할 수 있어야 한다. 최종 빌드에서는 기본 비활성화한다.

## 10. 범위 보호

### 임의 추가 금지

추가 구종, 직접 타격·수비·주루, 다수 구단·경기장, 자유 이동, 경제·아이템, 장기 시즌, 부상, 관계도, 스킬 트리, SNS·인터뷰, 서버·계정·멀티플레이, 생성형 AI·외부 API와 전체 보이스오버를 추가하지 않는다.

### 삭제 금지 핵심

모든 경기 투구 직접 조작, 세 구종, 첫 실패, 행동 기회 2회, 성장 차이, 비고정 2군·최종 결과, 두 실패 지점·생존 엔딩, 책임 판정, 저장·복귀, 실제 사건 커뮤니티와 Android 터치를 유지한다.

### 우선 단순화 가능

관중 애니메이션, 기사 썸네일, 배경 파티클, 비핵심 전환, 추가 표정, 음악 변형, 프로그램 장식과 비핵심 밈을 먼저 단순화한다. 확정 기능을 줄이면 소유 문서도 함께 갱신한다.

## 11. 충돌 처리

충돌 우선순위와 권위 문서 소유권은 `docs/game_design/INDEX.md`의 「충돌 처리」를 따른다.

- 핵심 결과가 달라지는 충돌을 임의 해결하지 않는다.
- 의미가 같은 용어 차이는 소유 문서 용어로 통일한다.
- 없는 수치는 `[가정]`으로 분리한다.
- 충돌 해결 시 관련 문서를 함께 갱신한다.

## 12. AI 작업 규칙

작업 전 소유 문서, 선행 모듈, 입력·출력·예외와 최소 수용 검사를 확인한다. 구현 중 화면 코드에 경기 판정을 넣지 않고, 데이터를 조건문으로 복제하거나 전역 난수를 사용하지 않으며, 오류를 정상 결과로 숨기지 않는다.

완료 시 자동 검사 또는 재현 절차, 로그, 기존 종단 경로와 문서 일치를 확인한다. 실제 기기 검사가 필요하면 완료라고 단정하지 않는다.

## 13. 공통 완료 정의

- 입력 데이터 정의
- 핵심 로직과 다음 시스템 연결
- 정상·실패·예외 경로
- 원인 로그
- 해당 시 동일 결과 재현
- 저장 대상의 저장·불러오기
- 불변 조건 준수
- 요청 범위 밖 기능 미추가

보이기만 하거나 로그에만 있고 실제 결과에 반영되지 않는 기능은 완료로 간주하지 않는다.

## 14. 최종 수용 조건

- [확정] 새 게임부터 첫 프롤로그, 강등, 휴대폰과 프로그램으로 진행한다.
- [확정] 두 행동 기회와 성장·무성장 경로가 2군 평가에 연결된다.
- [확정] 2군과 최종 결과가 정상 판정으로 성공·실패한다.
- [확정] 생존과 두 실패 엔딩으로 연결된다.
- [확정] 실책·불운·책임이 퀘스트와 반응에 일관되게 쓰인다.
- [확정] 휴대폰 미열람 경로도 같은 결과를 얻는다.
- [확정] 앱 중단 후 정의된 체크포인트로 복귀한다.
- [확정] 같은 상태·시드·입력으로 결과를 재현한다.
- [확정] Android 가로 화면에서 오프라인으로 전체 경로를 완주한다.
- [검증 필요] 실제 기기에서 투구 입력, 30FPS, 가독성, 오디오와 복귀를 확인한다.

## 15. 문서 범위

이 문서에는 실제 코드로 옮길 구현 규칙과 검증 가능한 수용 조건만 기록한다.
