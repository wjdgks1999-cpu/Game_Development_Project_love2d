# ADR-0002: 구현 계약·콘텐츠·검증 문서를 분리한다

- 상태: 승인됨
- 결정일: 2026-08-16
- 적용 범위: `docs/game_design`

## 배경

기존 GDD는 게임의 목표와 규칙을 충분히 설명하지만, AI가 구현할 때 필요한 계산 순서, 이벤트 코드, 콘텐츠 필드, 준비 상태, 검증 증거가 여러 문서에 흩어져 있었다. 이 내용을 각 권위 문서에 모두 넣으면 문서가 지나치게 길어지고 중복이 늘어난다.

## 결정

다음 문서를 별도 구현 자료로 둔다.

1. `contracts/01_match_resolution_contract.md`
2. `contracts/02_game_event_contract.md`
3. `contracts/03_community_content_schema.md`
4. `content/CONTENT_REQUIREMENTS.md`
5. `VALIDATION_MATRIX.md`

관련 GDD 절에는 세부사항을 위 문서에서 읽으라는 짧은 안내를 넣고, `INDEX.md`가 문서 트리와 읽기 경로를 관리한다.

## 이유

- 원래 GDD의 읽기 길이를 크게 늘리지 않는다.
- AI가 작업 종류에 맞는 세부 문서를 바로 찾을 수 있다.
- 게임 규칙과 구현 형식의 소유권을 구분한다.
- 미정 콘텐츠와 검증 상태를 한곳에서 확인할 수 있다.

## 영향

- 새 문서는 기존 권위 GDD를 덮어쓰지 않는다.
- 새 계산값이나 콘텐츠는 원문의 `[확정]`, `[가정]`, `[미정]`, `[검증 필요]` 상태를 따른다.
- 실제 콘텐츠 제작, 기술 환경·버전 고정, 코드 구현은 이번 결정의 범위가 아니다.
- 중요한 규칙이 바뀌면 권위 GDD를 먼저 고치고 관련 계약, 요구사항, 검증 매트릭스를 함께 갱신한다.

## 승인 근거

2026-08-16 문서 검토에서 사용자가 제안된 모든 문서 분리안을 승인하고, 관련 GDD 안내와 `INDEX.md` 트리 갱신을 요청했다.
