# GDD 결정 기록 안내

## 목적

이 폴더는 승인된 중요 게임 디자인 변경의 이유, 근거와 영향을 기록한다. 최종 게임 규칙은 항상 `docs/game_design/INDEX.md`가 지정한 권위 GDD에 있으며, 결정 기록은 그 규칙을 복제하거나 대체하지 않는다.

결정 기록 작성은 새로운 승인 게이트가 아니다. 기존 설계 변경 승인 후 권위 GDD를 갱신할 때 함께 남기는 변경 이력이다.

## 기록하는 변경

- `[확정]`된 핵심 게임 규칙의 변경
- 버티컬 슬라이스 시작·종료, 포함·제외 범위 또는 완료 기준의 변경
- 최종 품질과 임시 품질 경계의 변경
- 엔딩, 평가 퀘스트 또는 주요 커리어 분기의 변경
- 여러 시스템이 소비하는 수치나 사건 계약의 변경
- 프롤로그 예외 같은 핵심 예외의 추가·삭제
- 권위 문서의 소유권 이전
- 사용자 플레이 결과로 핵심 경험이나 설계 방향을 변경한 결정

## 별도 기록하지 않는 변경

- 오탈자와 의미가 바뀌지 않는 표현 정리
- 파일 링크와 섹션 참조 수정
- 구현 계획만의 작업 순서와 파일 배치
- 아직 `[가정]`인 수치를 실험하는 과정
- 승인된 설계 범위 안의 일시적인 밸런스 실험

실험 결과가 확정 규칙으로 승격되거나 여러 시스템의 계약을 바꾸면 그때 결정 기록을 작성한다.

## 파일 이름

```text
NNNN-짧은-결정-이름.md
```

예:

```text
0001-adjust-second-team-evaluation.md
```

번호는 기존 기록의 다음 번호를 사용한다. 기존 기록을 폐기하지 않고, 새 결정에서 `대체하는 결정`으로 연결한다.

## 기록 형식

```markdown
# DD-NNNN: 결정 제목

- 상태: 승인됨 / 대체됨
- 날짜: YYYY-MM-DD
- 권위 문서: `docs/game_design/<file>.md#section`
- 사용자 승인 근거: 현재 작업 또는 관련 커밋
- 대체하는 결정: 없음 / `DD-NNNN`

## 변경

- 이전:
- 이후:

## 이유와 증거

- 플레이테스트 또는 자동 검증:
- 변경 이유:

## 영향

- 함께 확인할 소비 문서:
- 구현 및 재검증 범위:
```

## 운영 순서

1. `docs/game_design/INDEX.md`에서 권위 문서를 확인한다.
2. 기존 설계 승인 게이트에서 사용자와 변경을 승인한다.
3. 중요 변경이면 이 폴더에 결정 기록을 작성한다.
4. 같은 작업에서 권위 GDD를 현재 규칙으로 갱신한다.
5. 소비 문서에는 값 복제 대신 권위 문서 참조를 남긴다.
6. 구현과 검증은 갱신된 권위 GDD를 기준으로 진행한다.

결정 기록만 작성하고 권위 GDD를 갱신하지 않은 상태로 구현을 진행하지 않는다.
