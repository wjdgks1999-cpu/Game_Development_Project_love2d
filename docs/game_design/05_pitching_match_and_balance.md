# 투구·경기 판정·밸런스

## 1. 문서 목적

이 문서는 버티컬 슬라이스의 직접 투구 조작, 실제 투구 위치, 타자 대응, 타구와 자동 수비, 투수 책임 판정 및 등판별 난이도를 정의한다.

핵심 목표는 다음과 같다.

1. 모든 투구에서 플레이어의 선택과 입력이 의미를 가진다.
2. 선수 능력치는 플레이어의 실력을 대체하지 않고 투구의 안정성을 변화시킨다.
3. 좋은 결과와 나쁜 결과의 원인을 플레이어가 이해할 수 있다.
4. 첫 1군 등판을 제외한 경기 결과는 사전에 고정하지 않는다.
5. 성장 전후의 차이를 숫자뿐 아니라 실제 조작 감각으로 전달한다.

---

## 2. 핵심 판정 원칙

### 2.1 모든 공의 직접 조작

- [확정] 플레이어가 담당하는 모든 투구를 직접 수행한다.
- [확정] 자동 투구와 결과만 보여주는 투구는 사용하지 않는다.
- [확정] 모든 구종은 같은 기본 조작 구조를 사용한다.
- [확정] 구종별 차이는 입력 속도, 성공 판정 폭, 움직임과 결과 특성으로 표현한다.

### 2.2 플레이어 실력과 선수 능력치

플레이어와 선수 능력치의 역할을 다음처럼 구분한다.

| 요소 | 주요 역할 |
| --- | --- |
| 구종·코스 선택 | 타자의 노림수 회피와 볼카운트 운영 |
| 릴리스 입력 | 실제 위치가 목표점에서 벗어나는 기본 방향과 크기 |
| 제구 | 성공 판정 폭과 최대 산포 |
| 구종 숙련도 | 해당 구종의 산포, 구속과 움직임 안정성 |
| 구위 | 헛스윙 유도와 타구 질 억제 |
| 구속 | 타자의 반응 시간과 포심 위력 |
| 멘탈 | 위기 상황의 입력 안정성과 추가 오차 |
| 체력·피로 | 링 속도, 성공 판정 폭과 최대 오차 |
| 컨디션 | 해당 등판의 전반적인 능력치 보정 |
| 제한된 난수 | 같은 입력에서 발생할 수 있는 작은 편차 |

- [확정] 좋은 능력치가 명백하게 나쁜 입력을 자동으로 성공시키지 않는다.
- [확정] 낮은 능력치에서도 좋은 입력과 전략으로 2군 평가를 통과할 수 있다.
- [확정] 성장했다고 경기 성공을 보장하지 않는다.
- [검증 필요] 일반적인 플레이에서는 입력 차이가 제구 결과의 가장 큰 원인으로 느껴져야 한다.
- [검증 필요] 능력치 성장은 같은 수준의 입력을 더 안정적인 결과로 바꿔야 한다.

### 2.3 판정의 정직성

- [확정] 성공을 만들기 위한 강제 범타를 사용하지 않는다.
- [확정] 실패를 만들기 위한 강제 볼넷·피안타·장타를 사용하지 않는다.
- [확정] 예외는 과거의 고정된 실패를 재현하는 첫 프롤로그 등판에만 적용한다.
- [확정] 좋은 입력을 실투로 허위 표시하지 않는다.
- [확정] 수비 실책이나 불운을 투수의 실투로 허위 표시하지 않는다.

## 3. 경기 화면과 시점

### 3.1 기본 카메라

- [확정] 화면은 가로 모드로 고정한다.
- [확정] 카메라는 홈플레이트의 포수 머리 위치에서 마운드를 바라본다.
- [확정] 투수는 화면 안쪽 마운드에 있고 공은 카메라를 향해 날아온다.
- [확정] 좌타자와 우타자는 타석 방향에 맞춰 화면 한쪽 전경에 전신으로 표시한다.
- [확정] 타자는 `08_mobile_ui_art_and_audio.md`의 공통 SD 디자인을 따르는 전신 SD 액션 스프라이트로 표현한다.

### 3.2 포구 표현

- [확정] 포수의 몸과 미트 캐칭 애니메이션은 표시하지 않는다.
- [확정] 공이 도착하면 포구음과 짧은 화면 효과로 포구를 표현한다.
- [확정] 스트라이크·볼 판정은 포구 직후 심판 음성과 UI로 전달한다.

## 4. 한 투구의 전체 단계

정확한 계산 순서, 입력·좌표 정의, 프롤로그 예외, 테스트 벡터는 `contracts/01_match_resolution_contract.md`를 따른다.

한 투구는 다음 순서로 진행한다.

| 단계 | 플레이어 행동 | 시스템 처리 | 주요 피드백 |
| --- | --- | --- | --- |
| 1. 상황 확인 | 카운트, 주자, 타자 성향 확인 | 최근 배합과 타자 상태 표시 | 타자 정보, 포수 사인 |
| 2. 구종 선택 | 포심·슬라이더·체인지업 선택 | 구종별 예상 궤적과 상태 확인 | 구종 버튼, 예상 구속 |
| 3. 목표 설정 | 스트라이크존 주변을 드래그 | 목표 위치 제한과 터치 보정 | 손가락 위 목표 마커 |
| 4. 투구 시작 | 투구 버튼 터치 | 투구 모션과 릴리스 링 시작 | 링 축소, 모션, 사운드 |
| 5. 릴리스 | 적절한 순간에 다시 터치 | 입력 오차 계산 | 성공 등급과 릴리스 효과 |
| 6. 투구 판정 | 없음 | 실제 위치와 궤적 계산 | 목표점과 실제 위치 |
| 7. 타자 대응 | 없음 | 지켜보기·스윙·컨택 판정 | 타자 반응과 타격음 |
| 8. 결과 처리 | 없음 | 볼·스트라이크·파울·타구 처리 | 카운트 또는 타구 다이어그램 |
| 9. 상태 갱신 | 다음 투구 준비 | 멘탈·피로·배합·로그 갱신 | 상태 단계와 결과 원인 |

- [확정] 타자 결과가 끝난 뒤에만 다음 투구 선택으로 이동한다.
- [확정] 타구가 발생하지 않은 투구는 포수 시점 안에서 계속 진행한다.
- [확정] 타구가 발생하면 별도 수비 화면을 불러오지 않는다.

## 5. 터치 조작

### 5.1 양손 기본 배치

- [확정] 양손 조작을 우선한다.
- [가정] 한쪽 엄지는 구종 선택과 목표 코스 설정에 사용한다.
- [가정] 반대쪽 엄지는 투구 시작과 릴리스 입력에 사용한다.
- [확정] 좌우 버튼 배치를 바꿀 수 있게 한다.
- [확정] 구종마다 다른 제스처를 요구하지 않는다.

### 5.2 목표 코스

- [확정] 투명한 스트라이크존과 주변 목표 영역을 표시한다.
- [확정] 목표 영역은 스트라이크존 바깥 약 공 한 개 너비까지 허용한다.
- [확정] 실제 투구는 입력 실패와 선수 상태에 따라 목표 영역보다 더 벗어날 수 있다.
- [확정] 목표점은 칸 선택이 아니라 연속적인 위치로 지정한다.
- [확정] 목표 마커는 손가락보다 위에 표시해 손가락에 가리지 않게 한다.
- [확정] 목표 지점을 자동으로 스트라이크존 안에 붙이는 강제 스냅은 사용하지 않는다.

### 5.3 투구 시작과 릴리스

1. 구종을 선택한다.
2. 목표 위치를 드래그해 지정한다.
3. 투구 버튼을 눌러 투구 모션을 시작한다.
4. 투수 주위의 원형 릴리스 링이 줄어든다.
5. 기준 지점에 도달할 때 다시 터치한다.
6. 두 번째 터치 시점으로 릴리스 오차를 계산한다.

- [확정] 투구 시작 후에는 목표 코스를 변경할 수 없다.
- [확정] 릴리스 링은 구종과 현재 상태에 따라 속도와 성공 폭이 달라진다.
- [확정] 입력 접수는 화면 프레임이 아니라 실제 시간 기준으로 계산한다.
- [확정] 터치 지연과 프레임 변동이 판정 결과를 바꾸지 않도록 시간값을 보정한다.

### 5.4 입력 등급

릴리스 기준 시점과 실제 입력 시점의 차이를 정규화한 값을 `R`이라 한다.

- `R < 0`: 빠른 릴리스
- `R = 0`: 중심 릴리스
- `R > 0`: 늦은 릴리스

초기 판정 구간은 다음과 같이 가정한다.

| 정규화 오차 | 입력 등급 | 기본 결과 |
| --- | --- | --- |
| `|R| ≤ 0.20` | 정확 | 목표점 주변의 능력치 산포만 적용 |
| `0.20 < |R| ≤ 0.55` | 양호 | 작은 방향 오차 추가 |
| `0.55 < |R| ≤ 1.00` | 불안정 | 뚜렷한 방향 오차 추가 |
| `|R| > 1.00` | 실수 | 큰 오차가 발생하지만 최대 범위 안으로 제한 |

- [가정] 세부 경계값은 실제 모바일 기기 테스트로 조정한다.
- [확정] 빠른 릴리스는 높은 쪽·투수 기준 팔 쪽 오차를 만든다.
- [확정] 늦은 릴리스는 낮은 쪽·투수 기준 글러브 쪽 오차를 만든다.
- [확정] 오차 방향은 화면 방향이 아니라 투수의 투구 방향을 기준으로 정의한다.

## 6. 실제 투구 위치

### 6.1 기본 공식

실제 도착 위치는 다음 요소의 합으로 계산한다.

`실제 위치 = 목표 위치 + 릴리스 방향 오차 + 제구·숙련도 산포 + 멘탈·피로 상황 오차`

각 요소의 역할은 다음과 같다.

#### 목표 위치

플레이어가 드래그로 지정한 의도된 포구 위치다.

#### 릴리스 방향 오차

- 입력 시점이 빠르거나 늦은 정도에 따라 방향과 크기가 정해진다.
- 입력 오차가 커질수록 비선형적으로 증가한다.
- 같은 수준의 빠른 입력과 늦은 입력은 서로 다른 방향의 실투를 만든다.

#### 제구·숙련도 산포

- 제구는 모든 구종의 기본 산포를 줄인다.
- 구종 숙련도는 해당 구종의 추가 산포를 줄인다.
- 산포는 재현 가능한 난수로 정해진 제한된 타원 범위 안에서만 발생한다.
- 능력치가 높아도 산포가 완전히 0이 되지는 않는다.

#### 멘탈·피로 상황 오차

- 멘탈이 낮으면 성공 판정 폭이 줄고 상황 오차가 커진다.
- 피로가 높으면 링 속도와 최대 산포가 증가한다.
- 멘탈과 피로만으로 자동 볼넷이나 자동 실투가 발생하지는 않는다.

### 6.2 오차 제한

- [확정] 제한된 난수가 명백한 실투의 유일한 원인이 되어서는 안 된다.
- [확정] 작은 난수 산포만으로 반대쪽 타석까지 날아가는 결과를 만들지 않는다.
- [확정] 큰 실투에는 큰 입력 오차, 낮은 상태 또는 둘의 결합이 존재해야 한다.
- [확정] 실제 위치가 크게 벗어나면 결과 화면에서 가장 큰 원인을 우선 표시한다.

### 6.3 결과 피드백

중요한 투구에는 다음 정보를 제공한다.

- 선택한 구종
- 목표 위치
- 실제 위치
- 입력 등급
- 빠름·정확·늦음
- 제구와 숙련도 영향
- 멘탈·피로 영향
- 타자의 노림 여부
- 최종 결과
- 실투 또는 좋은 타자 대응 여부

모든 정보를 매 투구 긴 문장으로 표시하지 않는다. 기본 화면에서는 핵심 원인만 보여주고, 상세 투구 로그에서 전체 정보를 확인할 수 있게 한다.

## 7. 구종

### 7.1 포심 패스트볼

| 항목 | 초기 설정 |
| --- | --- |
| 구속 | 약 143~147km/h |
| 움직임 | 비교적 작고 직선적 |
| 릴리스 링 | 빠르지만 성공 판정 폭이 가장 넓음 |
| 제구 | 세 구종 중 가장 안정적 |
| 주요 역할 | 스트라이크 확보, 높은 코스 승부, 변화구와의 배합 |
| 위험 | 반복 시 타자의 노림수와 강한 타구 가능성 상승 |

### 7.2 슬라이더

| 항목 | 초기 설정 |
| --- | --- |
| 구속 | 약 128~134km/h |
| 움직임 | 우투수 기준 글러브 쪽으로 늦게 크게 변화 |
| 릴리스 링 | 성공 판정 폭이 가장 좁음 |
| 제구 | 현재 숙련도가 낮아 산포가 큼 |
| 주요 역할 | 결정구, 낮고 바깥쪽 유인, 포심과의 터널 |
| 위험 | 가운데 몰리면 장타 위험, 과도하게 벗어나면 쉽게 골라냄 |

### 7.3 체인지업

| 항목 | 초기 설정 |
| --- | --- |
| 구속 | 약 124~131km/h |
| 움직임 | 포심과 비슷하게 출발한 뒤 가라앉음 |
| 릴리스 링 | 포심보다 느리며 성공 판정 폭은 중간 |
| 제구 | 낮은 신뢰도와 숙련도로 편차가 존재 |
| 주요 역할 | 타이밍 교란, 포심 대비 속도 차이 |
| 위험 | 구속 차이와 위치가 부족하면 강한 타구 허용 |

### 7.4 구속 판정

실제 구속은 다음 요소로 정한다.

- 구종의 기본 구속 범위
- 선수의 구속 능력치
- 해당 구종 숙련도
- 피로와 컨디션
- 릴리스 입력
- 제한된 난수 편차

- [확정] 구속은 km/h로 표시한다.
- [확정] 정확한 릴리스는 구종의 정상 구속을 안정적으로 낸다.
- [확정] 심한 입력 실패와 높은 피로는 구속을 소폭 낮출 수 있다.
- [확정] 구속 난수는 구종 정체성이 바뀌지 않는 작은 범위로 제한한다.

### 7.5 구위

구위는 단순히 구속과 같은 수치가 아니다.

구위가 높으면 다음 효과를 가진다.

- 타자의 반응 가능 시간 감소
- 헛스윙 가능성 증가
- 같은 컨택에서도 정타 가능성 감소
- 포심의 공 끝과 변화구의 후기 움직임 강화

구위가 낮다고 자동 피안타가 발생하지 않으며, 좋은 코스와 배합으로 보완할 수 있다.

## 8. 포수 사인과 타자 정보

### 8.1 포수 사인

- [확정] 포수 사인은 권고 구종과 코스를 제공한다.
- [확정] 플레이어는 사인을 따르거나 무시할 수 있다.
- [확정] 사인을 무시해도 직접적인 능력치 페널티는 없다.
- [확정] 포수 사인이 항상 정답인 것은 아니다.
- [확정] 버티컬 슬라이스에는 포수 관계도나 호흡 수치를 구현하지 않는다.

포수 사인은 다음 정보를 제한적으로 반영한다.

- 타자의 공개 성향
- 현재 볼카운트
- 앞선 구종 배합
- 기본적인 위험 회피
- 주자 상황

### 8.2 타자 정보

각 등판에 필요한 실제 타자 데이터의 준비 상태는 `content/CONTENT_REQUIREMENTS.md`를 확인한다.

플레이어에게는 타자마다 최대 두 개의 대표 성향만 공개한다.

예:

- 빠른 공에 강함
- 바깥쪽 변화구에 약함
- 초구 적극적
- 2스트라이크 이후 끈질김
- 낮은 공을 잘 참음

다음 정보는 직접 공개하지 않는다.

- 정확한 컨택·파워·선구안 수치
- 현재 노리고 있는 구종과 코스
- 내부 스윙 확률
- 다음 행동의 확정 결과

플레이어는 타자의 스윙 타이밍, 헛스윙, 파울과 지켜보기 반응으로 숨은 성향을 추론한다.

## 9. 구종 배합과 피칭 터널

### 9.1 타자의 학습

타자는 같은 타석과 최근 타석의 투구 기록을 바탕으로 노림수를 갱신한다.

- 같은 구종을 반복하면 해당 구종 예상 확률이 상승한다.
- 비슷한 코스를 반복하면 해당 구역 예상 확률이 상승한다.
- 유리한 카운트에서 반복된 패턴은 더 빠르게 학습한다.
- 단순 반복이라도 실제로 좋은 코스에 들어가면 무조건 실패하지는 않는다.
- 반복은 확정 페널티가 아니라 타자의 대응 확률을 높인다.

### 9.2 피칭 터널

다음 투구가 이전 투구와 초반 궤적이 비슷하고 후반에 다르게 움직이면 터널 효과가 발생한다.

대표 조합:

- 높은 포심 이후 낮게 떨어지는 체인지업
- 바깥쪽 포심 이후 같은 출발점에서 벗어나는 슬라이더
- 변화구 이후 같은 출발점의 포심

터널 효과는 다음에 영향을 준다.

- 타자의 판단 시점 지연
- 헛스윙 가능성 증가
- 정타 가능성 감소
- 노림수가 빗나갔을 때의 약한 타구 증가

- [확정] 별도의 피칭 터널 게이지는 표시하지 않는다.
- [확정] 타자의 반응과 경기 후 투구 분석으로 효과를 알려준다.
- [확정] 구종 이름만으로 터널 효과를 주지 않고 실제 코스와 초반 궤적을 비교한다.

## 10. 타자 AI

### 10.1 투구 전 판단

각 투구 전 타자는 다음 내부 상태를 선택한다.

1. 예상 구종
2. 예상 코스 구역
3. 적극적으로 칠지 지켜볼지에 대한 접근 방식

선택에는 다음 요소가 사용된다.

- 타자의 성향과 능력치
- 현재 볼카운트
- 이전 구종과 코스
- 반복 패턴
- 투수의 현재 구종 사용 비율
- 주자와 아웃카운트
- 2군·1군 타자 수준

### 10.2 노림수 결과

#### 구종과 코스를 모두 맞힌 경우

- 스윙 판단이 빨라진다.
- 헛스윙 가능성이 감소한다.
- 강한 타구 가능성이 상승한다.

#### 일부만 맞힌 경우

- 일반적인 대응 판정을 사용한다.
- 타자 능력과 실제 투구 질이 결과를 결정한다.

#### 노림수를 피한 경우

- 판단이 늦어진다.
- 헛스윙·파울·약한 타구 가능성이 상승한다.
- 좋은 타자는 노림수가 빗나가도 파울로 버틸 수 있다.

### 10.3 지켜보기와 스윙

타자는 다음 순서로 판단한다.

1. 투구가 자신의 예상과 얼마나 일치하는지 계산
2. 실제 궤적이 스윙 가능 범위에 들어오는지 판단
3. 볼카운트와 성향을 반영해 지켜보기 또는 스윙 선택
4. 스윙했다면 헛스윙·파울·인플레이 판정
5. 인플레이면 타구 질 계산

- [확정] 타자는 최종 위치를 미리 알지 못한다.
- [확정] 타자의 반응은 투구가 진행되는 동안 확인 가능한 정보로 결정한다.
- [확정] 높은 선구안은 유인구를 더 잘 참게 하지만 모든 볼을 자동으로 골라내지는 않는다.

## 11. 볼카운트와 경기 상황

### 11.1 카운트 효과

볼카운트는 결과를 직접 보정하지 않고 타자와 투수의 판단 상태에 영향을 준다.

| 상황 | 타자 변화 | 투수 변화 |
| --- | --- | --- |
| 초구 | 성향에 따라 적극성 차이 | 기본 상태 |
| 투수 유리 | 유인구 대응 범위 확대, 파울 방어 증가 | 공격적 선택 가능 |
| 타자 유리 | 특정 구종·코스를 강하게 노림 | 볼넷 압박 증가 |
| 3볼 | 지켜보기 확률 상승 | 멘탈 부담 증가 |
| 2스트라이크 | 스윙 범위와 파울 가능성 상승 | 결정구 선택 가치 증가 |
| 풀카운트 | 타자 보호 스윙 증가 | 멘탈 부담과 투구 중요도 상승 |

- [확정] 3볼이라고 스트라이크가 자동으로 넓어지지 않는다.
- [확정] 2스트라이크라고 같은 투구가 자동으로 헛스윙이 되지 않는다.
- [확정] 심판의 스트라이크존은 고정한다.
- [제외] 심판별 가변 존, 포수 프레이밍과 오심은 구현하지 않는다.

### 11.2 주자와 아웃카운트

주자가 출루하면 다음 변화가 발생한다.

- 실점 위험과 투구 중요도 상승
- 주인공의 멘탈 부담 증가
- 타자의 접근 방식 변화
- 자동 주루 판정 활성화

아웃카운트가 늘어나면 멘탈을 일부 회복한다. 단, 위기 상황에서 발생한 아웃 하나가 멘탈을 즉시 완전히 회복시키지는 않는다.

- [확정] 안타와 타구 결과에 따른 주루는 자동 처리한다.
- [제외] 도루, 견제, 번트, 런다운과 수동 주루는 구현하지 않는다.
- [제외] 폭투와 포일은 버티컬 슬라이스의 기본 경기 판정에서 제외한다.

## 12. 멘탈

### 12.1 내부 수치와 표시 단계

멘탈은 내부적으로 연속 수치로 계산하지만 플레이어에게는 네 단계로 표시한다.

| 내부 안정도 가정 | 표시 단계 | 영향 |
| --- | --- | --- |
| 75~100 | 안정 | 기본 입력과 산포 |
| 50~74 | 흔들림 | 성공 폭 소폭 감소, 상황 오차 증가 |
| 25~49 | 위기 | 성공 폭 감소, 링과 산포 불안정 증가 |
| 0~24 | 붕괴 | 가장 큰 페널티가 적용되지만 자동 실패는 없음 |

- [가정] 단계 경계와 효과량은 플레이 테스트로 조정한다.
- [확정] 내부 수치를 실시간 숫자로 공개하지 않는다.
- [확정] 단계 변화는 UI, 호흡음과 짧은 화면 효과로 전달한다.

### 12.2 멘탈 감소 요인

- 볼넷
- 연속 볼
- 주자 출루
- 강한 타구 허용
- 실투 이후 장타
- 득점권 위기
- 리드 상실
- 중요한 카운트에서의 나쁜 입력

### 12.3 멘탈 회복 요인

- 정확한 릴리스
- 공격적인 스트라이크
- 헛스윙
- 삼진
- 아웃카운트 확보
- 위기 상황 종료
- 조건을 충족한 멘탈 패시브

좋은 입력 직후 불운한 안타가 발생한 경우, 입력에 대한 소량의 회복과 출루에 대한 감소를 별도로 계산한다. 이를 통해 좋은 입력을 했다는 사실을 완전히 무시하지 않는다.

## 13. 피로

### 13.1 표시 단계

피로 역시 내부적으로 연속 계산하되 네 단계로 표시한다.

| 내부 피로도 가정 | 표시 단계 | 영향 |
| --- | --- | --- |
| 0~24 | 여유 | 기본 상태 |
| 25~49 | 보통 | 미세한 구속·산포 변화 |
| 50~74 | 피로 | 링 속도와 최대 산포 증가 |
| 75~100 | 한계 | 구속, 성공 폭과 구종 안정성에 큰 영향 |

### 13.2 피로 증가

- 투구 수
- 구종별 소모량
- 긴 타석
- 높은 압박 상황
- 등판 전 컨디션

- [가정] 슬라이더는 포심보다 약간 높은 피로를 사용한다.
- [가정] 체인지업은 포심과 비슷하거나 약간 낮은 피로를 사용한다.
- [확정] 한 이닝 안에서도 투구 수가 지나치게 늘면 피로를 체감할 수 있어야 한다.
- [확정] 피로가 높아도 결과를 자동 실패로 바꾸지 않는다.

## 14. 타격 판정

### 14.1 지켜본 투구

타자가 스윙하지 않으면 실제 도착 위치와 고정 스트라이크존으로 볼·스트라이크를 판정한다.

- 스트라이크존 내부: 스트라이크
- 스트라이크존 외부: 볼
- 경계선 판정은 일관된 설정값을 사용한다.

### 14.2 스윙한 투구

스윙 결과는 다음 요소로 계산한다.

- 실제 투구 위치
- 구속과 구위
- 구종 움직임
- 피칭 터널
- 타자의 구종·코스 노림수
- 타자의 컨택 능력
- 볼카운트에 따른 접근 방식
- 제한된 난수

판정 순서는 다음과 같다.

`스윙 → 헛스윙 또는 접촉 → 파울 또는 인플레이 → 타구 질`

### 14.3 타구 질

타구 질은 다음 요소를 조합한다.

- 배트 중심과 공의 접촉 차이
- 타자의 파워
- 구종과 구속
- 실제 코스
- 노림수 일치 여부
- 투구의 구위
- 입력에 의한 실투 여부

타구 질은 내부적으로 연속값을 사용하며 다음 범주로 요약한다.

- 빗맞음
- 약한 타구
- 보통 타구
- 강한 타구
- 완벽한 타구

타구 질이 좋다고 항상 안타가 되지는 않으며, 약한 타구도 수비 위치에 따라 안타가 될 수 있다.

## 15. 인플레이와 자동 수비

### 15.1 타구 생성

인플레이 타구에는 다음 값을 생성한다.

- 땅볼·직선타·뜬공·홈런 후보
- 타구 속도
- 방향
- 발사각
- 체공 시간
- 예상 착지 지점

### 15.2 수비 단순화

- [확정] 버티컬 슬라이스에서는 개별 야수 능력치를 사용하지 않는다.
- [확정] 하나의 팀 수비력 수치를 사용한다.
- [확정] 타구 위치에 따라 담당 수비수를 자동 선택한다.
- [확정] 타구 속도·방향·체공 시간과 팀 수비력을 조합해 도달 가능성을 계산한다.

기본 판정 순서는 다음과 같다.

1. 타구 종류와 착지 지점 계산
2. 담당 수비수 결정
3. 도달 가능 여부 계산
4. 도달했다면 포구 또는 낮은 확률의 실책 판정
5. 도달하지 못했다면 안타 종류와 자동 주루 계산
6. 투수 책임과 결과 원인 태그 기록

### 15.3 실책

- [확정] 실책은 수비수가 도달 가능한 공에서만 발생한다.
- [확정] 매우 강해서 처리하기 어려운 타구를 무조건 실책으로 기록하지 않는다.
- [가정] 기본 실책 확률은 낮게 유지하고 타구 난도에 따라 조정한다.
- [확정] 실책으로 발생한 출루는 투수의 실투와 별도로 기록한다.

### 15.4 자동 수비 결과 태그

아래 한국어 의미를 코드에 기록할 때의 표준 태그와 필드는 `contracts/02_game_event_contract.md`를 따른다.

다음 태그를 경기 로그에 남긴다.

- 정상 수비
- 실책
- 야수 선택
- 수비 범위 부족
- 빗맞은 안타
- 강한 타구
- 투수 실투에서 발생한 타구
- 타자의 좋은 대응
- 불운성 타구
- 포수 사인 적중 또는 불일치

한 사건에는 모순되지 않는 범위에서 여러 태그를 동시에 사용할 수 있다.

## 16. 타구 다이어그램

타구 다이어그램은 타격 이후 타구 궤적과 자동 수비 판정을 짧게 보여주는 구장 오버레이다. 별도의 수비 게임 화면이 아니다.

### 16.1 전환

1. 타격이 발생한다.
2. 같은 프레임 또는 다음 렌더 프레임에 포수 시점 배경을 어둡게 한다.
3. 동시에 단순 구장 다이어그램을 오버레이로 표시한다.
4. 타구 궤적과 담당 수비수의 이동을 표시한다.
5. 포구·낙구·실책과 주루 결과를 표시한다.
6. 자동으로 포수 시점으로 복귀한다.

- [확정] 별도 장면 로딩을 사용하지 않는다.
- [확정] 검은 화면과 긴 페이드를 사용하지 않는다.
- [확정] 타격음부터 이동음·포구음까지 소리를 끊지 않는다.
- [가정] 기본 표시 시간은 약 0.8~1.5초를 목표로 한다.
- [확정] 주자 이동 설명이 필요하면 표시 시간을 제한적으로 늘릴 수 있다.
- [확정] 화면 터치로 결과 표시를 빠르게 넘길 수 있다.
- [확정] 의무적인 계속 버튼을 두지 않는다.

### 16.2 표시 정보

- 단순화된 구장
- 타구 시작점과 궤적
- 담당 수비수
- 주자 이동
- 아웃·안타·실책 결과
- 필요한 경우 결과 원인 태그

## 17. 투수 책임 판정

### 17.1 기록상 실점과 평가상 책임

경기 기록과 퀘스트 판정을 위해 다음을 구분한다.

1. 실제 경기에서 발생한 실점
2. 기록상 투수에게 부과되는 실점
3. 퀘스트·구단 평가에서 사용하는 투수 책임 사건
4. 실책 또는 명백한 불운이 주원인인 사건

### 17.2 실책 처리

수비 실책이 발생하면 실제 아웃과 별도로 `책임 판정용 가상 아웃`을 기록한다.

- 정상적으로 처리했으면 아웃이었을 타구는 가상 아웃으로 계산한다.
- 가상 아웃이 3개가 된 이후의 실점은 투수 책임 퀘스트에서 제외한다.
- 투수의 앞선 볼넷이나 실투가 실점에 직접 기여했다면 해당 책임을 별도로 남긴다.

### 17.3 명백한 불운

명백한 불운은 다음처럼 제한적으로 판정한다.

- 좋은 위치와 정상 입력에서 발생한 매우 약한 타구
- 수비수가 정상적으로 도달하기 어려운 위치에 떨어진 빗맞은 안타
- 투수의 실투나 볼넷이 선행 원인이 아닌 사건

- [확정] 불운성 안타 자체는 실제 경기 기록에서 삭제하지 않는다.
- [확정] 수비 실책이나 명백한 불운만으로 발생한 실패는 퀘스트 책임 판정에서 보호한다.
- [확정] 실투, 볼넷 또는 강한 타구가 함께 원인이면 무조건 불운으로 면제하지 않는다.

### 17.4 주요 원인 우선순위

결과 화면에서는 다음 순서로 핵심 원인을 결정한다.

1. 명백한 릴리스 실수
2. 낮은 멘탈·높은 피로로 확대된 오차
3. 타자의 노림수 적중
4. 타자의 좋은 대응
5. 강한 타구
6. 수비 실책
7. 수비 범위 부족
8. 빗맞은 안타 또는 명백한 불운

원인 우선순위는 사건을 단순화해 보여주기 위한 것이며, 상세 로그에는 복수 원인을 함께 기록한다.

## 18. 등판별 난이도

### 18.1 난이도 원칙

- [확정] 리그에 따라 릴리스 입력을 몰래 불리하게 만들지 않는다.
- [확정] 2군과 1군의 차이는 주로 타자 능력과 AI 판단에서 발생한다.
- [확정] 숨은 연승·연패 보정과 동적 난이도 보정을 사용하지 않는다.
- [확정] 첫 프롤로그 예외 규칙은 이후 등판에 적용하지 않는다.

### 18.2 첫 1군 프롤로그

- 성장 전의 낮은 제구와 변화구 숙련도를 사용한다.
- 출루 이후 멘탈이 흔들리는 경험을 강조한다.
- 결과는 최소 동점 이상의 리드 상실로 고정된다.
- 실패 과정, 투구 수와 실점 규모는 플레이에 따라 달라진다.

### 18.3 2군 평가

2군 타자는 다음 특성을 가진다.

- 비교적 낮은 선구안
- 비교적 낮은 컨택과 장타력
- 느린 노림수 갱신
- 반복 패턴에 대한 낮은 적응력
- 유인구에 대한 높은 반응 가능성

- [확정] 훈련하지 않은 상태에서도 좋은 직접 투구로 통과할 수 있다.
- [확정] 훈련했다고 자동으로 통과하지 않는다.

### 18.4 최종 1군 등판

1군 타자는 다음 특성을 가진다.

- 높은 선구안과 컨택
- 유인구에 대한 절제된 반응
- 빠른 구종 배합 학습
- 노림수 적중 시 높은 강한 타구 가능성
- 노림수가 빗나가도 파울로 버틸 가능성

최종 등판은 첫 등판과 다른 타자 구성을 사용하며, 첫 프롤로그의 결과 순서를 반복하지 않는다.

### 18.5 성장 전후 차이

성장은 다음 조작 요소에 직접 반영한다.

- 릴리스 성공 판정 폭
- 제구 산포의 평균과 최대치
- 슬라이더·체인지업 움직임의 안정성
- 구속 편차
- 실투 이후 멘탈 감소량
- 아웃 이후 멘탈 회복량
- 피로 누적
- 조건부 패시브 효과

- [검증 필요] 같은 입력 표본에서 성장 후 상위 오차 범위가 성장 전보다 분명히 줄어야 한다.
- [검증 필요] 사용자가 능력치 화면을 보지 않아도 성장 전후 차이를 느낄 수 있어야 한다.

## 19. 첫 등판 고정 실패 예외

### 19.1 프롤로그 연출

첫 등판은 과거에 이미 발생한 실패를 플레이하는 프롤로그다.

다음 표현으로 과거임을 암시한다.

- 과거 날짜 표시
- 현재 구간과 구분되는 절제된 색감
- “그날의 8회”처럼 과거를 암시하는 문장
- 짧은 기록 화면 또는 회상형 전환
- 경기 종료 후 현재 시점으로 복귀하는 연출

첫 투구 전에 “어떤 입력을 해도 패배한다”고 직접 선언하지는 않는다.

### 19.2 예외 판정

- [확정] 일반 투구 판정으로 실제 위치, 볼넷, 피안타와 타구 질을 계산한다.
- [확정] 플레이에 따라 실패 과정과 실점 규모가 달라진다.
- [확정] 세 번째 아웃 전에 최소 한 점 이상의 투수 책임 실점이 발생하도록 역사적 사건 제약을 적용한다.
- [확정] 나쁜 입력이 있으면 해당 입력과 자연스럽게 연결되는 실패 사건을 우선한다.
- [확정] 좋은 입력만 이어졌다면 타자의 좋은 대응처럼 해당 투구와 모순되지 않는 사건을 사용한다.
- [확정] 좋은 입력을 실투로 바꾸거나 허위 실투 태그를 붙이지 않는다.
- [확정] 프롤로그 제약이 작동한 사실은 개발 로그에 기록한다.

최소 리드 상실 이후에는 일반 판정을 사용해 이닝 종료 또는 감독의 교체까지 진행한다. 이에 따라 동점만 허용하거나 추가 실점하는 등 실패의 정도가 달라진다.

### 19.3 이후 경기와의 분리

프롤로그가 끝난 뒤 다음 의미를 전달한다.

> 과거의 결과는 바꿀 수 없었다. 하지만 다음 등판은 아직 결정되지 않았다.

- [확정] 2군 평가부터 역사적 사건 제약을 완전히 비활성화한다.
- [확정] 2군과 최종 1군 등판에는 강제 성공·실패 사건을 사용하지 않는다.
- [확정] 같은 판정 코드를 사용하되 프롤로그 제약은 명시적인 별도 상태로 격리한다.
- [검증 필요] 플레이어가 첫 등판만 예외이고 이후 결과는 공정하다고 이해하는지 확인한다.

## 20. 난수와 재현성

### 20.1 경기 시드

- [확정] 각 등판을 시작할 때 경기 난수 시드를 생성한다.
- [확정] 같은 선수 상태, 같은 경기 시드와 같은 입력 순서라면 같은 결과를 재현할 수 있어야 한다.
- [확정] 재시도 시에는 기본적으로 새로운 시드를 사용한다.
- [확정] 개발 빌드에서는 같은 시드와 새로운 시드를 선택할 수 있다.

### 20.2 난수 분리

가능하면 난수 흐름을 다음처럼 분리한다.

- 투구 산포
- 타자 판단
- 컨택과 타구
- 수비와 실책
- 템플릿 반응

UI 효과나 사운드가 경기 판정용 난수 순서를 변경해서는 안 된다.

### 20.3 제한 원칙

- 난수는 정해진 최대 범위 안에서만 사용한다.
- 난수만으로 좋은 입력이 명백한 실투가 되지 않는다.
- 희귀 사건도 로그에서 사용한 시드와 판정 근거를 확인할 수 있어야 한다.

- 폭투와 포일

- 세 구종 외 추가 구종

## 26. 완료 기준

이 문서는 다음 조건을 만족하면 구현 기준으로 사용할 수 있다.

- [확정] 세 구종으로 모든 투구를 직접 수행할 수 있다.
- [확정] 목표 위치와 실제 위치가 분리되어 계산된다.
- [확정] 입력, 능력치, 상태와 제한된 난수가 판정식에 반영된다.
- [확정] 타자가 볼카운트와 앞선 배합에 따라 반응한다.
- [확정] 헛스윙·파울·타구와 자동 수비가 처리된다.
- [확정] 타구 다이어그램이 포수 시점 위에 즉시 표시된다.
- [확정] 실책·불운·실투·좋은 타자 대응을 구분한다.
- [확정] 2군과 최종 1군 등판 결과를 사전에 고정하지 않는다.
- [확정] 첫 등판의 고정 실패 예외가 다른 등판과 분리된다.
- [확정] 같은 시드와 입력으로 경기 결과를 재현할 수 있다.
- [확정] 성장 전후 차이가 실제 조작과 판정에 반영된다.
- [검증 필요] 실제 모바일 기기에서 조작 반응성과 결과 납득성을 확인한다.
