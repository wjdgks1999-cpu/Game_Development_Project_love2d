# 통합 검증 매트릭스

## 1. 목적

이 문서는 여러 GDD에 흩어진 `[검증 필요]` 항목을 구현·테스트 목표로 묶어 상태와 증거를 관리한다. 원문 기대 동작을 대신하거나 바꾸지 않는다.

상태는 `대기`, `준비`, `진행`, `통과`, `실패`, `보류` 중 하나를 사용한다. 사용자 테스트에 필요한 인원과 수치 기준이 아직 확정되지 않은 경우 `[미정]`으로 두며, 최종 승인 전에 반드시 정한다.

## 3. 운영 규칙

1. 근거 문서의 `[검증 필요]` 문장은 그대로 유지하고 이 표의 ID로 묶는다.
2. `[검증 필요]`는 원칙적으로 프로토타입 구현을 막지 않으며, `차단 지점`에 적힌 게이트의 최종 통과를 막는다.
3. `통과`에는 재현 가능한 증거 위치와 실행 조건이 필요하다.
4. 기대 동작이 바뀌면 권위 GDD를 먼저 수정한 뒤 방법과 통과 기준을 갱신한다.
5. 측정 수치나 표본 수가 `[미정]`이면 해당 최종 게이트를 통과 처리하지 않는다.
6. 실패를 숨기기 위해 기준을 낮추지 않는다. 기준 변경에는 이유와 결정 기록을 남긴다.
