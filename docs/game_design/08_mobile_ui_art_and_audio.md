# 모바일 UI·아트·사운드

## 1. 문서 목적

Android 가로 화면에서 사용하는 경기·훈련·퀘스트·휴대폰·서사 UI와 캐릭터, 배경, 애니메이션, 사운드 및 진동 표현을 정의한다.

핵심 목표는 작은 화면에서 투수·타자·공·스트라이크존을 명확히 읽고, 양손 조작이 화면을 가리지 않으며, 현실·프로그램·휴대폰 UI를 구분하고, 제한된 에셋으로 투구 손맛과 성장 차이를 전달하는 것이다.

## 2. 플랫폼·화면

- [확정] Android 우선, 가로 모드 고정, 양손 조작 우선이다.
- [확정] 좌우 조작 버튼 묶음을 교환할 수 있다.
- [확정] 내부 논리 해상도는 1280×720이다.
- [확정] 핵심 경기 구도와 HUD는 중앙 16:9 안전 영역에 둔다.
- [확정] 넓은 화면에서는 배경만 좌우로 확장하며 캐릭터·UI 비율을 왜곡하지 않는다.
- [확정] 노치·카메라 홀·시스템 제스처 영역을 실행 시 안전 여백으로 반영한다.
- [확정] 극단적인 화면비에서만 최소한의 레터박스를 허용한다.

## 3. 터치 영역

- 버튼의 실제 터치 영역은 시각적 크기보다 넓게 한다.
- 목표 마커는 손가락보다 위에 표시한다.
- 투구 중 시스템 제스처 오작동을 막을 가장자리 여백을 둔다.
- 릴리스 입력은 프레임이 아니라 실제 시간으로 판정한다.

1280×720 기준 초기 가정:


| 요소                  | 최소 터치 영역 |
|-------------------------|----------------------|
| 투구 버튼           | 약 112×112         |
| 구종 버튼           | 약 96×72           |
| 일시정지            | 약 72×72           |
| 닫기·다음          | 약 144×72          |
| 작은 보조 아이콘 | 약 64×64           |


- [가정] 실제 기기의 물리 크기와 화면 밀도로 조정한다.
- 기본은 왼쪽에 구종·사인·목표, 오른쪽에 투구·릴리스를 둔다.
- 좌우 전환 시 하단 조작 묶음만 교환하고 경기 구도는 유지한다.

## 4. 경기 카메라

- [확정] 카메라는 홈플레이트의 포수 머리 위치에서 마운드를 바라본다.
- [확정] 투수는 화면 안쪽, 공은 카메라 방향으로 이동한다.
- [확정] 좌·우타자는 타석 쪽 전경에 전신으로 표시한다.
- [확정] 포수의 몸과 미트는 표시하지 않는다.

가독성 우선순위는 투수 동작, 스트라이크존과 공, 타자 스윙, 조작 UI, 경기 정보, 배경 순이다. 공은 실제 비율보다 약간 크게 표시할 수 있고 짧은 외곽선·잔상으로 배경과 분리한다. 릴리스·포구·강한 타구에는 짧은 강조만 사용하며 지속 흔들림, 큰 줌, 강한 플래시와 긴 슬로모션은 사용하지 않는다.

## 5. 경기 HUD


| 위치           | 정보·조작                         |
|------------------|----------------------------------------|
| 상단 왼쪽    | 볼·스트라이크·아웃과 주자 |
| 상단 중앙    | 이닝과 점수                       |
| 상단 오른쪽 | 멘탈·피로와 일시정지         |
| 하단 왼쪽    | 세 구종과 포수 사인            |
| 중앙           | 스트라이크존과 목표 마커    |
| 하단 오른쪽 | 투구 시작·릴리스 버튼        |


- 투구 전에는 타자 성향, 사인, 구종과 상태를 표시한다.
- 투구 시작 후에는 릴리스 링과 투수 동작만 선명하게 하고 비핵심 정보 명도를 낮춘다.
- 포구 직후 스트라이크·볼·헛스윙·파울, 구속, 입력 방향과 주요 원인을 짧게 표시한다.
- 멘탈과 피로는 색상뿐 아니라 단계 이름, 아이콘 형태와 패턴으로 구분한다.
- 포수 사인은 권고 정보이며 무시해도 경고창이나 부정 효과를 사용하지 않는다.

## 6. 포구와 타구 다이어그램

- 포수 몸 없이 포구음, 짧은 원형 충격과 심판 판정으로 포구를 표현한다.
- 타격 직후 같은 프레임 또는 다음 렌더 프레임에 배경을 어둡게 하고 구장 다이어그램을 동시에 표시한다.
- 별도 장면 로딩, 검은 화면과 페이드를 사용하지 않는다.
- 타격음부터 이동·포구음까지 끊지 않는다.
- 기본 표시 시간은 약 0.8~1.5초이며 터치로 가속할 수 있다.
- 단순 구장, 타구 경로, 수비수, 주자 이동과 결과만 표시한다.

- [확정] 화면 간 이동은 선형 흐름과 명확한 버튼으로 처리한다.

## 8. 일상 대화

- 고정 장소 배경, 허리 위 초상, 화자 이름과 하단 대화창을 사용한다.
- 화면 터치로 진행하고 대화 기록과 장면 건너뛰기를 제공한다.
- 중요한 선택지가 없는 선형 장면으로 구성한다.
- 한 화면의 본문은 모바일에서 한 번에 읽을 수 있는 분량으로 제한한다.
- 재시도에서는 이미 본 장면을 자동으로 건너뛸 수 있다.

## 9. 캐릭터 표현

### 9.1 공통

경기용과 일상용 캐릭터는 하나의 캐릭터 정체성을 공유하지만 동일한 신체 비율과 세부 묘사를 그대로 사용하지 않는다.

일상용은 인물의 성격, 감정과 상호작용을 전달하는 것을 우선하고, 경기용은 작은 화면에서 야구 동작과 방향을 즉시 판독하는 것을 우선한다. 하나의 일상용 캐릭터 이미지를 단순 축소하거나 변형해 경기용으로 사용하지 않고, 공통된 캐릭터 정체성을 기준으로 각 용도에 맞는 별도의 표현 규격을 사용한다.

두 표현 사이에서 다음 요소는 캐릭터 정체성 기준으로 유지한다.

- 얼굴의 핵심 특징
- 머리 모양과 주요 헤어 실루엣
- 머리·피부·의상의 대표 색상
- 의상의 기본 구조와 주요 배색
- 캐릭터를 식별하는 고유 특징과 장식
- 지정된 등번호
- 투타 방향과 글러브를 포함한 장비 방향성

다음 요소는 용도에 따라 의도적으로 다르게 표현할 수 있다.

- 머리와 몸의 비율
- 몸통과 팔다리 길이
- 손과 발의 크기
- 글러브와 배트 등 장비의 표시 크기
- 얼굴과 의상의 세부 묘사량
- 명암 단계
- 포즈의 과장 정도

체형의 정체성은 유지하되 정확한 신체 비율까지 일치시킬 필요는 없다. 예를 들어 마른 체형, 단단한 체형과 같은 인상은 공유하되 경기용에서는 동작 가독성을 위해 팔다리와 몸통 비율을 재구성할 수 있다.

이 문서는 게임 프로젝트에서 사용할 최종 표현과 수용 기준만 정의한다. 외부 제작 도구의 설치·호출·비용·상태와 로그는 게임 프로젝트 문서의 범위에 포함하지 않는다.

#### 9.1.1 주인공 기준선

- [확정] `02_protagonist_and_career_structure.md`에서 정의한 주인공 설정을 정체성·화풍 기준 시트, 대화 초상과 경기용 SD 스프라이트에 공통 적용한다.
- [확정] 주인공 소속 구단의 홈 유니폼은 아이보리 몸체, 짙은 남색 소매·파이핑과 제한적인 탁한 적색 강조를 사용한다.
- [확정] `02_protagonist_and_career_structure.md`에 정의된 등번호를 유니폼의 지정된 뒤 위치에 고정하고, 우투수의 왼손 글러브는 모든 필요한 동작과 표시 각도에서 유지한다.
- [확정] 실제 구단 표식, 임의 글자, 문신·장신구·수염, 염색·장발, 과장된 근육과 실사 화풍은 기준선에서 제외한다.

#### 9.1.2 두 표현 사이의 변환 원칙

- 일상용 캐릭터와 경기용 캐릭터는 서로의 축소판이나 확대판으로 취급하지 않는다.
- 일상용에서 확정된 얼굴 특징, 헤어 실루엣, 대표 색상, 의상 구조와 고유 특징을 캐릭터 정체성의 기준으로 삼고, 경기용에서는 이를 작은 화면과 야구 동작에 적합한 compact SD 형태로 다시 해석한다.
- 경기용에서 필요한 큰 장비, 짧은 팔다리와 강한 액션 실루엣을 일상용 캐릭터에 그대로 적용할 필요는 없다.
- 두 표현을 나란히 보았을 때 동일한 인물로 인식되어야 하지만 머리:몸 비율과 세부 묘사량까지 동일할 필요는 없다.
- 새로운 캐릭터는 일상용과 경기용 중 한 표현만 독립적으로 확정하지 않고, 최소한 두 표현의 대표 기준 이미지를 함께 비교해 정체성 일치를 확인한 뒤 양산한다.

### 9.2 경기용

- [확정] 포수 시점에 최적화한 compact 전신 SD 액션 스프라이트를 사용한다.
- [확정] 경기용 캐릭터의 최우선 목표는 실제 게임 표시 크기에서 현재 자세와 야구 동작을 즉시 읽을 수 있게 하는 것이다.
- [확정] 경기용 정보 우선순위는 `동작 실루엣 → 장비 → 몸의 방향 → 캐릭터 대표 색상과 유니폼 → 얼굴 세부` 순으로 한다.
- [확정] 머리, 손, 발, 글러브와 배트는 작은 화면의 판독성을 위해 실제 인체·장비 비율보다 크게 표현할 수 있다.
- [확정] 몸통과 팔다리는 현실적인 해부학적 비율보다 동작선과 포즈 판독을 우선해 압축하거나 과장할 수 있다.
- [확정] 투구 팔, 글러브, 다리 들기, 중심 이동, 릴리스와 팔로스루가 각 키포즈에서 서로 다른 실루엣으로 읽혀야 한다.
- [확정] 타자는 준비, 스윙, 컨택과 팔로스루에서 팔·배트·몸통이 만드는 큰 방향성이 명확해야 한다.
- [확정] 세부적인 얼굴 표정보다 머리 실루엣, 대표 색상, 유니폼과 장비를 통해 캐릭터 정체성을 우선 유지한다.
- [확정] 얼굴의 핵심 특징은 가능한 범위에서 유지하되 실제 게임 표시 크기에서 얼굴만으로 인물을 구분할 것을 필수 조건으로 하지 않는다.
- [확정] 보이는 지정된 등번호와 우투수의 왼손 글러브 등 플레이와 설정에 영향을 주는 특징은 필요한 각도에서 판독 가능해야 한다.
- [확정] 제한 프레임을 사용하되 대기, 투구와 타격 동작의 의미가 실제 재생 속도에서 읽혀야 한다.

### 9.3 일상용

- [확정] 성격, 감정과 인물 간 상호작용을 강조하는 표현력 있는 cartoon-style SD 일러스트를 사용한다.
- [확정] 일상용 정보 우선순위는 `얼굴과 표정 → 머리와 고유 실루엣 → 상체 자세와 손동작 → 의상과 장식` 순으로 한다.
- 장면에 맞는 허리 위, 반신 또는 필요한 범위의 상체 중심 구도를 사용한다.
- 얼굴에서는 눈, 눈썹, 입과 시선 방향을 주요 감정 정보로 사용한다.
- 고개 각도, 상체 기울기, 팔 위치와 손동작을 표정과 함께 사용해 감정과 상대 인물에 대한 반응을 표현한다.
- 캐릭터를 구분하는 머리 실루엣, 대표 색상, 의상 구조와 고유 특징은 경기용과 공유한다.
- 경기용과 동일한 정확한 신체 비율을 사용할 필요는 없으며, 일상용에서는 얼굴과 제스처를 읽기 위한 공간을 더 확보한다.
- 경기용보다 머리카락, 의상, 장식과 명암의 세부 밀도를 높일 수 있으나 작은 모바일 화면에서 형태가 뭉개질 정도의 미세 묘사는 사용하지 않는다.
- 승인된 소수의 얼굴·팔·고개 레이어를 재사용하며 입 모양 풀 애니메이션과 전체 보이스오버는 구현하지 않는다.

|-------------|--------------------------------|
| 주인공   | 중립, 불안, 지침, 결의 |
| 감독      | 냉정, 제한적 인정       |
| 1군 코치 | 지적, 관찰                 |
| 2군 코치 | 설명, 경고, 인정         |
| 포수      | 집중, 격려                 |

총 13개 표정 변형을 목표로 한다. 기사 프로필은 주인공 중립 초상을 재사용한다.

## 10. 경기 애니메이션

- 경기용 캐릭터는 승인된 2D 정체성 기준 시트와 승인된 대표 경기 기준 프레임을 바탕으로 최종 런타임용 투명 PNG 프레임과 스프라이트 시트로 제작한다.
- 모든 프레임은 동일한 캐릭터 정체성, 대표 색상, 유니폼 구조, 장비 방향, 피벗과 발 기준선을 유지한다.
- 경기용으로 확정된 머리:몸 비율, 팔다리 비율과 장비 과장 정도는 같은 캐릭터의 전체 경기 프레임에서 유지한다.
- 프레임마다 독립적으로 크롭·재중심화하거나 캐릭터의 경기용 기본 비율과 장비 크기를 임의로 변경하지 않는다.
- 각 키포즈는 중간 프레임 없이 한 장만 보더라도 동작 단계가 가능한 한 구분되어야 한다.
- 자유 이동용 방향 세트를 만들지 않고 포수 시점과 실제 사용 장면에 필요한 자세와 동작만 제작한다.
- 투수는 세트, 시작, 다리 들기, 중심 이동, 팔 넘김, 릴리스, 팔로스루와 회복의 약 8개 키포즈를 사용한다.
- 구종마다 다른 투구 모션을 만들지 않고 궤적과 움직임으로 차이를 표현한다.
- 타자는 대기, 준비, 스윙, 컨택, 팔로스루, 헛스윙·파울·인플레이 반응을 사용한다.
- 좌·우타자는 기본 동작을 반전할 수 있으나 문자, 손, 타석과 장비 비대칭을 수정한다.
- 공은 하나의 기본 스프라이트에 거리별 크기, 선명도, 회전과 짧은 잔상을 적용한다.
- 관중 개별 애니메이션은 제외하고 작은 반복 움직임과 사운드로 표현한다.

## 11. 배경

최종 배경은 네 장소로 제한한다.

1. 경기장: 세 경기와 직접 훈련
2. 1군 더그아웃·면담 공간: 첫 등판, 강등, 재콜업, 최종 평가
3. 2군 훈련장·면담 공간: 일정, 훈련과 2군 평가
4. 주인공 개인 공간: 휴대폰, 프로그램 발현과 독백


엔딩 전용 배경은 만들지 않고 기존 배경의 색감·크롭·명도와 초상을 재조합한다.

## 12. UI 시각 체계

### 12.1 현실 경기·구단

짙은 남색, 아이보리, 회색과 제한적인 붉은 강조색을 사용한다. 방송 중계·구단 분석 화면처럼 정렬된 기록과 절제된 패널을 사용한다.

### 12.2 프로그램

반투명 검정, 청록·청색 선과 각진 기하학 패널을 사용한다. 글리치·스캔선은 최초 발현에만 짧게 사용하며 지속적으로 텍스트를 방해하지 않는다. 휴대폰 알림과 SNS 표현을 섞지 않는다.

### 12.3 휴대폰

밝은 회색·흰색, 현실적인 알림 배지와 기사·커뮤니티 카드 구조를 사용한다. 가로 화면 안에 확대된 앱 패널을 표시한다. 첫 강등에서는 자동 진입하고 즉시 닫을 수 있으며, 재콜업과 최종 결과에서는 확인 여부를 선택한다.

### 12.4 구현·품질 계약

- HUD, 패널, 버튼, 게이지, 스트라이크존, 릴리스 링, 목표 마커와 타구 경로의 구조·상태·반응형 배치는 Lua 코드로 구현한다.
- 색상, 타이포그래피, 간격, 모서리, 선 두께, 그림자와 아이콘 규칙을 `ui-style-tokens`로 먼저 확정한다.
- 인물 초상, 배경, 고유 장식 모티프, 소수의 고유 아이콘과 얇은 텍스처 오버레이만 래스터 자산으로 사용한다.
- 생성된 전체 UI 스크린샷을 런타임 화면으로 사용하지 않는다.
- 1280×720 대표 경기 HUD를 기준 Android 기기에서 먼저 검증하고 통과한 시각 체계를 프로그램·휴대폰·대화 UI로 확장한다.

## 13. 화면 전환·앱 복귀

- 일반 전환은 약 0.15~0.25초의 짧은 페이드를 사용한다.
- 타구 다이어그램, 프로그램, 휴대폰 알림과 일시정지는 즉시 오버레이한다.
- 앱이 백그라운드로 가면 오디오·진동과 시간을 즉시 정지한다.
- 경기 복귀는 현재 타자 시작 시점, 훈련 복귀는 해당 12구 훈련 시작 시점이다.
- 동일한 난수 시드를 사용하고 완료된 이전 결과는 유지한다.
- Android 뒤로가기는 경기·훈련에서 일시정지, 휴대폰에서 이전·닫기, 타이틀에서 종료 확인으로 처리한다.

## 14. 튜토리얼

- 별도 연습장을 만들지 않고 첫 프롤로그 경기에서 단계적으로 안내한다.
- 첫 공은 구종, 두 번째 공은 목표 코스, 세 번째 공은 투구·릴리스를 설명한다.
- 이후 포수 사인, 타자 성향, 멘탈·피로와 타구 다이어그램을 실제 발생 시 안내한다.
- 필요한 UI만 밝게 하고 한 화면에 한 행동만 설명한다.
- 설명 중 경기 시간과 릴리스 링을 정지한다.
- 재시도부터 전체 설명을 건너뛸 수 있고 설정에서 다시 활성화할 수 있다.

## 15. 접근성·타이포그래피

- 색상과 함께 아이콘·문자·패턴을 사용한다.
- 높은 대비 릴리스 링, 공 외곽선, 자막 크기, 화면 흔들림·글리치 감소 옵션을 제공한다.
- 좌우 배치 전환, 진동 끄기, 타자 사이 일시정지와 튜토리얼 다시 보기를 제공한다.
- 모든 음성 정보는 시각적으로도 표시하고 음악·효과음·관중·UI 음량을 분리한다.
- 접근성 설정은 경기 확률을 바꾸지 않는다.
- 재배포 가능한 한글 고딕 계열을 본문에 사용한다.

## 16. 사운드

- [확정] 효과음과 음악은 사용자가 직접 제작한다.
- [확정] 게임 프로젝트는 오디오 자동 생성을 수행하지 않는다. 사용자가 제공하기 전까지 사운드 산출물은 미완료로 남기되 다른 시각·UI 구현을 막지 않는다.
- 사용자가 제공한 오디오는 별도 명세로 임포트, 길이·포맷·루프·음량·재생 시점과 실제 기기 믹싱을 검수한다.

### 16.1 경기

- 투구 준비 호흡, 유니폼·글러브 마찰, 발 디딤과 릴리스
- 공의 바람, 구종·구속 차이와 포구음
- 빗맞음·보통·강한 타격음, 파울과 타구 이동
- 야수 포구, 실책, 베이스 도달과 아웃
- 짧은 한국어 스트라이크·볼·아웃·삼진 판정음
- 기본 웅성임, 카운트 기대·긴장, 환호·탄식과 위기 탈출 관중음

타구 다이어그램에서도 사운드를 끊지 않는다. 전체 대사 보이스오버는 구현하지 않는다.

### 16.2 프로그램·휴대폰

- 프로그램 발현, 패널 생성, 퀘스트, 달성, 보상과 만료 효과음
- 현실적인 휴대폰 알림·진동, 카드 선택과 닫기
- 프로그램과 휴대폰은 서로 다른 음색을 사용한다.

### 16.3 음악·믹싱

첫 프롤로그, 2군 성장, 최종 등판과 엔딩의 제한된 음악을 사용한다. 우선순위는 투구·타격·포구, 심판, 필수 알림, 관중, 음악, 일반 UI 순이다. 심판과 강한 타구 때 다른 소리를 짧게 낮출 수 있다.

### 18.3 제작 경로와 크기

2. 캐릭터별 2D 정체성 기준 시트에서 얼굴 핵심 특징, 헤어 실루엣, 대표 색상, 의상 구조, 고유 특징과 장비 방향을 정의한다.
3. 일상용 대표 중립 초상과 경기용 대표 기준 프레임을 각각 제작하고 두 이미지를 나란히 비교해 동일 인물로 인식되는지 승인한다.
4. 1280×720 목업에서 두 표현의 실제 게임 표시 크기를 먼저 검증한다.
5. 실제 표시 크기를 바탕으로 원본 작업 해상도와 경기용 스프라이트 시트 셀 크기를 정한다.
6. 경기용 대표 기준 프레임에서 머리:몸 비율, 팔다리 길이, 손·발과 장비 크기, 피벗과 발 기준선을 고정한다.
7. 승인된 경기용 기준을 바탕으로 필요한 투구·타격 키포즈만 제작하고 최종 런타임용 투명 2D PNG 프레임과 스프라이트 시트로 정리한다.
8. 모든 경기 프레임의 스케일, 피벗, 발 기준선, 대표 색상, 유니폼과 장비 방향을 비교해 프레임 간 흔들림과 정체성 드리프트를 수정한다.
9. 일상용은 승인된 대표 중립 초상을 기준으로 필요한 표정, 시선, 고개, 팔과 손동작 변형을 제작한다.
10. 일상용과 경기용을 단순 확대·축소하여 서로 대체하지 않고 각각 승인된 표현 규격을 유지한다.
11. 실제 Android 표시 크기와 실제 재생 속도에서 정체성, 동작 판독성과 가독성을 최종 검증한 뒤 승인된 자산만 게임 프로젝트에 가져온다.

- UI는 Lua 코드 네이티브를 기본으로 하고 래스터는 초상·배경·장식에 한정한다.
- 게임 프로젝트에는 승인된 2D 런타임 자산과 필요한 출처·라이선스·버전·QA 인수 기록만 가져오며, 외부 제작 도구의 설정·로그·비밀값은 가져오지 않는다.

- [검증 필요] 보이는 지정된 등번호, 글러브 방향과 캐릭터의 주요 설정 특징이 필요한 장면에서 유지되는가?
- [검증 필요] 제한 프레임 애니메이션으로 대기, 투구와 스윙의 의미를 실제 재생 속도에서 읽을 수 있는가?
- [검증 필요] 경기용 애니메이션 프레임 사이에서 경기용 SD 비율, 대표 색상, 유니폼, 장비, 피벗과 발 기준선이 안정적으로 유지되는가?
- [검증 필요] Lua 대표 HUD가 1280×720 실제 기기에서 정보 계층, 대비, 터치 피드백과 장식 품질을 모두 만족하는가?
- [검증 필요] 포구와 타구 질을 소리로 구분할 수 있는가?
- [검증 필요] 진동이 입력을 방해하지 않고 음소거 상태에서도 모든 정보를 이해하는가?

## 20. 제외 범위

- 세로 모드와 한 손 조작 우선 설계
- 실시간 3D 캐릭터 런타임
- 픽셀 아트 강제와 도구 편의에 따른 고정 셀 크기 선결정
- 포수 몸·캐칭 애니메이션과 직접 수비
- 자유 이동 로비와 복잡한 허브
- 다른 화풍의 서사 일러스트
- 풀 프레임 고해상도 애니메이션과 관중 개별 애니메이션
- 구종별 다른 투구 모션
- 전체 대사 보이스오버
- 선택형 인터뷰와 긴 영상 컷신
- 다수 경기장·엔딩 전용 배경
- 지속적인 강한 글리치
- 생성된 전체 UI 스크린샷의 런타임 사용
- 온라인 알림과 실제 푸시 메시지

## 22. 완료 기준

- [확정] Android 가로 화면의 안전 영역과 가변 화면비에 대응한다.
- [확정] 양손 조작과 좌우 배치 전환이 동작한다.
- [확정] 포수 시점에서 투수·타자·공·스트라이크존을 읽을 수 있다.
- [확정] 경기용 compact 전신 SD와 표현력 있는 일상용 SD 초상은 서로 다른 표현 비율을 사용할 수 있으며 하나의 캐릭터 정체성을 유지한다.
- [확정] 얼굴 핵심 특징, 헤어 실루엣, 대표 색상, 의상 구조, 고유 특징과 장비 방향은 두 표현에서 일관되게 유지한다.
- [확정] 경기용은 실제 Android 표시 크기에서 얼굴 세부에 의존하지 않고 투수·타자의 자세와 주요 야구 동작을 판독할 수 있다.
- [확정] 경기용 머리·손·발과 장비는 동작 가독성을 위해 기능적으로 과장할 수 있으며 캐릭터별 경기 프레임 사이에서 같은 과장 규칙을 유지한다.
- [확정] 보이는 지정된 등번호와 우투수의 왼손 글러브 등 설정상 필요한 특징은 관련 장면에서 유지된다.
- [확정] 일상용은 얼굴, 시선, 고개, 상체 자세와 손동작으로 성격·감정·상호작용을 표현한다.
- [확정] 경기 애니메이션 프레임이 승인된 경기용 2D 기준의 비율, 대표 색상, 유니폼 구조, 장비 방향, 피벗과 발 기준선을 일관되게 유지한다.
- [확정] Lua 코드 네이티브 대표 HUD가 실제 기기 품질 게이트를 통과한 뒤 다른 UI 계열로 확장된다.
- [확정] 네 배경으로 전체 흐름을 표현한다.
- [확정] 현실·프로그램·휴대폰 UI를 시청각적으로 구분한다.
- [확정] 첫 경기에서 튜토리얼을 완료하고 타구 다이어그램을 즉시 표시한다.
- [확정] 앱 중단 후 같은 상태와 시드로 복귀한다.
- [확정] 사용자가 제작한 핵심 투구·타격·포구·심판·관중·프로그램·휴대폰 사운드가 존재한다.
- [확정] 진동 없이도 핵심 정보를 이해할 수 있다.
- [검증 필요] 실제 Android 기기에서 가독성, 터치 정확도, 프레임과 오디오를 확인한다.
